# CCB v8.4.3

Released: 2026-07-27

## English

### Managed Provider authentication

- Managed visible panes and headless Provider processes now select private
  HOME, XDG, Provider, session, storage, and credential roots.
- Allowlisted user credentials and account selections are inherited in one
  direction into ordinary agent-local state. Managed refresh, replacement, or
  logout cannot write back to the user's shell, IDE, another Agent, or another
  project.
- External keyrings are read-only inheritance sources. The narrowly scoped
  Claude macOS representation uses an Agent-derived service name and never
  replaces the user's ordinary Claude service.
- Unsupported or ambiguous credential backends fail closed. A Provider may
  require one managed-Agent login when no safe private import exists, but the
  external login remains unchanged.

### Required CCB controls

- Supported managed Agents receive the packaged `ask` and `ccb-clear` controls
  even when optional skill inheritance is disabled or restricted. Managed
  Codex also keeps its required `reconnect` control.
- Optional skills are projected per entry. A broken external skill cannot
  suppress CCB-owned controls or unrelated valid entries.
- Existing unrelated managed-home skills are preserved while exact CCB-owned
  entries are repaired from packaged release assets.

### Mobile pairing and terminal recovery

- Relay pairing can encode a compact signed-capability QR that fits a
  97-column terminal. CCB still writes an owner-only PNG fallback, and the
  Mobile app validates the compact capability before reconstructing the full
  pairing profile.
- Terminal snapshot state now uses synchronized generations, so a resize during
  capture produces one clean repaint instead of a stale delta.
- The Mobile client renews terminal handles after closed, output, or stream
  failures without surfacing a false terminal error to the user.

### Upgrade notes

- Existing project configuration requires no migration.
- Some managed Providers may request an Agent-local login when their external
  credential backend cannot be imported safely.
- npm-managed installations can run
  `npm install -g @seemseam/ccb@8.4.3`.
- Android users can install the signed CCB Mobile v8.4.3 APK from this release.

## 中文

### 托管 Provider 认证

- 托管 visible pane 与 headless Provider 进程现在统一使用私有 HOME、XDG、
  Provider、session、存储和凭据目录。
- 白名单内的用户凭据和账号选择只会单向继承到 Agent 私有状态。托管侧的
  刷新、替换或退出不会反向改写用户 shell、IDE、其他 Agent 或其他项目。
- 外部 keyring 只作为只读继承来源。macOS Claude 的受限例外使用按 Agent
  派生的服务名，不会替换用户自己的普通 Claude 服务。
- 不支持或存在歧义的凭据后端会安全拒绝。如果无法安全导入，Provider
  可能要求在托管 Agent 内登录一次，但不会改变外部登录态。

### 必备 CCB 控制能力

- 即使关闭或限制可选 skill 继承，受支持的托管 Agent 仍会获得内置
  `ask` 和 `ccb-clear`；托管 Codex 还会保留必需的 `reconnect`。
- 可选 skill 改为逐项投影，一个损坏的外部 skill 不会阻断 CCB 控制技能
  或其他有效条目。
- 修复准确的 CCB 自有条目时，会保留 managed home 内其他无关 skill。

### Mobile 配对与终端恢复

- Relay 配对可编码为适配 97 列终端的紧凑签名 capability 二维码。CCB
  仍会生成仅文件所有者可读的 PNG 兜底，手机端会先验证紧凑 capability，
  再恢复完整配对配置。
- Terminal snapshot 使用同步 generation，resize 与 capture 并发时会执行
  一次完整重绘，而不是发送基于旧尺寸的增量。
- 遇到 closed、output 或 stream 错误时，Mobile 会自动更新 terminal
  handle，不再把可恢复错误直接显示给用户。

### 升级说明

- 现有项目配置无需迁移。
- 如果某个外部凭据后端无法安全导入，对应托管 Provider 可能要求执行一次
  Agent 私有登录。
- npm 安装可执行：
  `npm install -g @seemseam/ccb@8.4.3`。
- Android 用户可从本 Release 安装签名后的 CCB Mobile v8.4.3 APK。
