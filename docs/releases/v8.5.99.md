# CCB v8.5.99

Released: 2026-08-01

Local preview build. The version number avoids a Git tag collision with the
published v8.5.2 and is not intended for publication.

## English

### Self-healing mailbox deliveries

- A delivery that never produced terminal completion evidence used to hold its
  mailbox head forever, starving every message queued behind it until a full
  daemon restart. Two independent nets now terminate such a delivery.
- The job heartbeat reaper is armed: a running `ask` that shows no observed
  session-log progress for roughly 60 minutes is terminated as `INCOMPLETE`.
  Any observed progress resets the window, and the work is never re-run.
- A message-type agnostic lease expiry sweep covers the classes the reaper
  cannot see, such as `task_reply` and `completion_notice`. An expired delivery
  is marked `ABANDONED` rather than `CONSUMED`, so a lost delivery is never
  disguised as success, and the mailbox queue advances.
- The sweep skips any Agent that still has a running job, so a healthy long
  delivery is never reaped.

### Operator timeout override

- `CCB_CLAUDE_NO_TERMINAL_TIMEOUT_S`, `CCB_CODEX_NO_TERMINAL_TIMEOUT_S`, and
  `CCB_GEMINI_NO_TERMINAL_TIMEOUT_S` now reach the daemon. The documented
  escape hatch was previously plumbed only for Pi, because the control-plane
  environment allowlist silently dropped the other variants.

### Upgrade notes

- No configuration migration is required.
- Restart already-running CCB projects after upgrading so the daemon loads the
  new reaper and lease sweep.
- A delivery terminated by either net is visibly non-successful. Inspect it and
  resubmit with `ccb repair` if the work still needs doing.

## 中文

### 自愈的邮箱投递

- 过去，一个始终没有产出终态完成证据的投递会永久占住邮箱队首，导致后面所有
  排队消息被饿死，只能靠完全重启 daemon 解决。现在有两道独立防线会终结它。
- job heartbeat reaper 已启用：运行中的 `ask` 如果约 60 分钟内没有观测到
  session log 进展，就会被判为 `INCOMPLETE`。任何观测到的进展都会重置该
  窗口，并且任务不会被重跑。
- 与消息类型无关的 lease 过期清扫覆盖 reaper 结构上看不到的类别，例如
  `task_reply` 和 `completion_notice`。过期投递被标记为 `ABANDONED` 而不是
  `CONSUMED`，因此丢失的投递不会被伪装成成功，同时邮箱队列得以放行。
- 清扫会跳过仍有运行中 job 的 Agent，因此健康的长时间投递不会被误杀。

### 运维超时开关

- `CCB_CLAUDE_NO_TERMINAL_TIMEOUT_S`、`CCB_CODEX_NO_TERMINAL_TIMEOUT_S` 和
  `CCB_GEMINI_NO_TERMINAL_TIMEOUT_S` 现在可以真正传达到 daemon。此前该逃生
  开关只对 Pi 生效，因为控制平面的环境变量白名单会静默丢弃其余变体。

### 升级说明

- 无需迁移现有配置。
- 升级后请重启已经运行的 CCB 项目，使 daemon 加载新的 reaper 和 lease 清扫。
- 被任一防线终结的投递会显式呈现为非成功状态。如果该任务仍需完成，请检查后
  用 `ccb repair` 重新提交。
