# v8.7.5

Released: 2026-09-30

## English

### OMP/Pi control-input reliability

- Opening `/model` or another control-only native selector no longer terminates an active OMP or Pi ask as superseded. The shared extension still binds recognized CCB dispatches immediately, but unmatched input alone is no longer treated as a replacement provider turn.
- A genuinely different prompt supersedes the active request only when it reaches the provider's `before_agent_start` lifecycle boundary. Explicit native `session_switch` events and later recognized CCB dispatches retain their existing replacement behavior and diagnostics.
- The fix is lifecycle-based rather than a `/model` command whitelist, so future control-only selectors do not need command-name exceptions.

### Verification and upgrade

- 302 focused Pi/OMP, runtime-launch, FIFO, and dispatcher regressions passed; two existing opt-in smoke tests were skipped. The generated Pi extension was executed with Bun to verify control input, real replacement turns, and native session switches, and the generated OMP extension was checked against the same boundary.
- In a disposable v8.7.5 source project, real OMP 18.3.5 switched from `paratera2/grok-4.6` to `bingxing/AWS-GPT-5.6-Sol` while job `job_727bce7356c0` was running a tool. The same attempt remained running, then completed once with exact reply `CCB_RELEASE_875_MODEL_SWITCH_OK`; no `request_superseded` event was emitted.
- Update CCB, then restart affected OMP/Pi panes or reopen the project when current work can safely be interrupted. Existing panes keep their already-loaded extension until restart. No project, conversation, or configuration migration is required.
- Android metadata and release assets remain synchronized with the coordinated release pipeline. This release adds no mobile UI behavior.

### Known limitations

- Pi uses the same repaired generated extension and passed Bun lifecycle replay plus pane-adapter regressions, but an authenticated real Pi TUI `/model` switch was not run separately for this release.
- The fix prevents false supersession; it does not make the entire native model-picker interaction atomic or recover unsaved drafts and in-flight provider operations after a process crash.

## 中文

### OMP/Pi 控制输入稳定性

- 打开 `/model` 或其他仅用于原生界面控制的选择器时，不再把正在执行的 OMP/Pi ask 误判为已被替换。共享扩展仍会立即绑定合法的 CCB 投递，但不会仅凭一条未匹配的输入事件终止当前任务。
- 只有不同的新提示真正到达 provider 的 `before_agent_start` 生命周期边界时，才会 supersede 当前请求。明确的原生 `session_switch` 事件和后续合法 CCB 投递仍保留原有替换语义及诊断信息。
- 修复依据生命周期边界，而不是维护 `/model` 命令白名单，因此未来新增的纯控制选择器无需逐个添加命令名称例外。

### 验证与升级

- 302 项 Pi/OMP、运行时启动、FIFO 和 dispatcher 聚焦回归通过；2 项原有的显式启用 smoke 测试跳过。测试使用 Bun 执行生成的 Pi 扩展，覆盖控制输入、真实替换回合和原生会话切换，并确认生成的 OMP 扩展采用相同边界。
- 在一次性 v8.7.5 源码项目中，真实 OMP 18.3.5 在任务 `job_727bce7356c0` 执行工具期间，从 `paratera2/grok-4.6` 切换到 `bingxing/AWS-GPT-5.6-Sol`。同一 attempt 在切换后保持 running，随后仅完成一次并精确返回 `CCB_RELEASE_875_MODEL_SWITCH_OK`，没有产生 `request_superseded` 事件。
- 更新 CCB 后，请在当前工作可以安全中断时重启受影响的 OMP/Pi pane，或重新打开项目。已有 pane 会继续使用启动时加载的旧扩展，直至重启。无需迁移项目、对话或配置。
- Android 元数据及发布产物继续使用现有统一发布流程；本版本没有新增手机端界面功能。

### 已知限制

- Pi 使用同一份已修复的生成扩展，并通过 Bun 生命周期回放及 pane adapter 回归，但本版本没有单独执行真实、已登录的 Pi TUI `/model` 切换。
- 本修复解决错误 supersede，不保证整个原生模型选择过程具备事务原子性，也不恢复进程崩溃前未提交的草稿或正在执行的 provider 操作。
