# v8.6.6

Released: 2026-08-15

## English

### Highlights

- A successful `ccb update` now restarts an already-running Mobile Host from
  the newly installed CCB source while preserving its route, host identity,
  and pairing. It does not start a stopped Host or replace a Host owned by a
  source checkout.
- Relay terminal streams now grant enough initial receive credit for every
  valid single message. Large terminal-history snapshots no longer wait for a
  credit update that cannot arrive until the first message is accepted.
- Claude can recover once when a dispatched prompt remains staged because its
  initial Enter was lost. The retry requires current-composer evidence for the
  exact task and does not turn the retry itself into activation (PR #305).

### Fixes and reliability

- Explicit `agents.<name>.env` values and Provider routes now remain above
  inherited Claude `settings.json` environment values (PR #307).
- A reused Agent binding is rebuilt when its normalized Provider profile has
  changed, including relative or `~` runtime-home paths. Conversation and
  restore policy remain intact (PR #308).
- Herdr now honors the exact requested non-root parent pane for nested splits
  (PR #309).
- Native Windows layouts can open provider-less `pwsh`, `powershell`, `bash`,
  and `wincmd` shell panes. Adding a Provider suffix still denotes an Agent, so
  names such as `bash:codex` remain compatible (PR #310).

### Upgrade notes

- No configuration, pairing, workspace, or conversation migration is
  required. Restart CCB after upgrading so changed Provider authority is
  evaluated for the next managed generation.
- Install the host with `npm install -g @seemseam/ccb@8.6.6`, or run
  `ccb update` from an existing release-package installation. Android users
  should install `ccb-mobile-v8.6.6.apk` from this Release so both ends use the
  corrected Relay window.

### Known limitations

- Android is the validated Mobile release target; iOS/iPadOS remain
  source-supported. Native Windows x64 remains beta and ships unsigned
  launchers.
- Claude's Enter recovery is deliberately limited to one retry and requires
  visible current-composer evidence. It does not guess activation from an idle
  pane or old transcript content.

## 中文

### 版本亮点

- `ccb update` 成功后，如果已安装版本的 Mobile Host 正在运行，会从新安装的 CCB
  源码重启，同时保留路由、Host 身份和配对信息；已停止的 Host 或由源码工作区拥有
  的 Host 不会被自动启动或替换。
- Relay 终端流的初始接收额度现在足以容纳任意一条合法消息。大型终端历史快照不再
  等待一个必须先接收首条消息才能产生的额度更新。
- Claude 提示已分发但首次 Enter 丢失时，可以执行一次恢复。补发必须在当前输入框
  中确认本任务的精确证据，并且补发本身不会被当作激活（PR #305）。

### 修复与稳定性

- 显式 `agents.<name>.env` 和 Provider 路由保持高于继承自 Claude
  `settings.json` 的环境变量（PR #307）。
- 复用的 Agent 绑定发现规范化后的 Provider profile 已变化时会重新构建；相对路径
  和 `~` runtime home 也会正确比较，同时保留对话及 restore 策略（PR #308）。
- Herdr 创建嵌套分割时会严格使用指定的非根父 Pane（PR #309）。
- 原生 Windows 布局可打开不带 Provider 的 `pwsh`、`powershell`、`bash` 和
  `wincmd` shell Pane；带 Provider 后缀时仍表示 Agent，因此 `bash:codex` 等名称
  保持兼容（PR #310）。

### 升级说明

- 无需迁移配置、配对信息、workspace 或对话历史。升级后请重启 CCB，使变化后的
  Provider 权威在下一次托管 generation 中重新判定。
- 主机可运行 `npm install -g @seemseam/ccb@8.6.6`，通过 Release 包安装的用户
  也可运行 `ccb update`。Android 用户应从本 Release 安装
  `ccb-mobile-v8.6.6.apk`，使两端都使用修正后的 Relay window。

### 已知限制

- Android 是经过验证的 Mobile 发布目标；iOS/iPadOS 仍为源码支持。原生 Windows
  x64 仍处于 beta，且启动器尚未签名。
- Claude 的 Enter 恢复严格限制为一次，并要求当前输入框存在可见证据；不会根据
  空闲 Pane 或旧 transcript 内容猜测任务已经激活。
