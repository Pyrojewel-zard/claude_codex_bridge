# CCB v8.4.0

Released: 2026-07-26

## English

### Highlights

- CCB Mobile now supports an end-to-end encrypted Relay transport with
  operator-issued one-time host invitations, bounded admission, multiplexed
  request, terminal, event, and file streams, plus official and self-hosted
  deployment modes. Relay operators cannot read task prompts, replies,
  terminal content, or transferred files.
- `ccb update mobile` owns route selection and setup. The computer guides
  Tailscale, a validated private LAN address, CCB Relay, or a self-hosted
  Relay; the phone only scans a QR code or enters a pairing code.
- Android can check for updates inside the app. Release metadata must come from
  the canonical GitHub repository, and the signed APK's exact size and SHA-256
  are verified before Android is asked to install it.
- Project identity remains stable when a CCB project directory is moved or
  renamed, with ambiguous or foreign identity claims rejected.

### Reliability and usability

- Relay host activation, reconnect, stream flow control, quotas, one-time
  invitation consumption, TLS bootstrap, and service rollback paths are
  bounded and covered by source and Flutter tests.
- Terminal, workbench, and Config UI surfaces can follow the operating
  system's light/dark appearance.
- Provider-affecting Config UI changes are recorded for the next CCB start,
  avoiding silent mutation of active panes.
- Opt-in Codex reconnect supervision is projected into managed Codex homes.
  It binds exact pane/session identity, retains only bounded terminal failure
  evidence, and refuses recovery when its input boundary cannot be proved.

### Upgrade notes

- No project data migration is required. Stable identity metadata is created
  and reconciled automatically when projects are discovered.
- Run `ccb update mobile` to select or change the route used by the computer.
  Official Relay invitations are issued out of band and consumed once during
  host activation; self-hosted operators issue their own invitations.
- Android updates still require user approval and a release signed with the
  established CCB Mobile signing key.
- npm-managed installations can run
  `npm install -g @seemseam/ccb@8.4.0`.

## 中文

### 主要更新

- CCB Mobile 新增端到端加密 Relay：支持运营方签发的一次性主机邀请码、有边界
  的接入控制、请求/终端/事件/文件多路复用流，以及官方和自建两种部署方式。
  Relay 运营方不能读取任务提示、回复、终端内容或传输文件。
- `ccb update mobile` 统一负责路由选择与配置。电脑端会引导设置 Tailscale、
  经过校验的局域网私网地址、CCB Relay 或自建 Relay；手机端只需扫码或输入
  配对码。
- Android App 支持应用内检查更新。Release 元数据必须来自官方 GitHub 仓库，
  并在交给 Android 安装前校验签名 APK 的准确大小与 SHA-256。
- CCB 项目目录移动或改名后仍保持稳定身份；模糊或外来的身份声明会被拒绝。

### 可靠性与易用性

- Relay 主机激活、断线恢复、流量窗口、配额、一次性邀请码消费、TLS 初始化和
  服务回滚路径均有明确边界，并由源码与 Flutter 测试覆盖。
- 终端、workbench 和 Config UI 可以跟随操作系统的浅色/深色外观。
- 会影响 Provider 的 Config UI 修改会记录为“下次 CCB 启动时应用”，不会静默
  改动正在运行的 pane。
- 可选的 Codex reconnect 监督会投射到托管 Codex home。它绑定准确的 pane/
  session 身份，只保留有边界的终端失败证据，并在无法证明输入边界时拒绝恢复。

### 升级说明

- 不需要迁移项目数据。发现项目时会自动创建并核对稳定身份元数据。
- 使用 `ccb update mobile` 选择或更换电脑端路由。官方 Relay 邀请码通过带外
  方式签发，并在主机激活时一次性消费；自建 Relay 由运营者自行签发邀请码。
- Android 更新仍需要用户确认，并要求 APK 使用既有 CCB Mobile 正式签名。
- npm 安装可执行：
  `npm install -g @seemseam/ccb@8.4.0`。
